# 电视媒资短视频创作 Agent 方案

## 目标与定位

在现有无限画布上建设一个面向电视媒体生产的短视频创作 Agent。用户给出选题、栏目要求与参考内容后，Agent 应能理解创作意图，检索已授权的电视媒资，产出解说文案、镜头候选、分镜和粗剪方案，并在画布中呈现和持续修改整条流程。

与通用视频生成 Agent 的核心差异是：成片的主要画面来源不是纯生成模型，而是电视媒资库中可追溯、可授权、可定位到时间码的视频资源；生成模型用于补足封面、转场、示意画面或无法从媒资获得的镜头。

首个目标不是全自动发布，而是让编导以更短时间完成“选题到可审片粗剪”的第一版，并保留对每条镜头、文案和素材来源的人工控制。

## 当前项目基础

| 已有能力 | 现状 | 在本方案中的作用 |
| --- | --- | --- |
| 无限画布 | 已有文本、图片、视频、音频、配置、分组节点及连线 | 承载创作简报、分镜、素材候选、剪辑片段和成片流程 |
| Canvas Agent | 已支持读取画布、批量增删改连线、创建生成流程和触发视频生成 | 作为编导 Agent 操作画布与编排流程的执行层 |
| Agent Skill | 已支持 Skill 的管理、启用和会话调用 | 封装影视解说、栏目包装、粗剪复核等稳定工作方法 |
| 视频生成 | 当前可使用图片、视频、音频参考生成短视频 | 用于补画面、补转场、做封面动效，不替代媒资剪辑 |
| 我的素材 | 已能保存文本、图片、视频，浏览器本地以 localforage 持久化 | 仅保存项目私有草稿、导入引用或导出副本，不作为媒资主库 |

当前缺口是媒资检索、授权校验、按时间码截取、时间线合成和制作审计。这些能力必须建立在媒体资源库接口之上，不能把高码率节目素材完整复制到浏览器本地。

### 现有能力的明确边界

- Agent 当前的对话附件只支持图片；视频素材、外部参考链接和媒资检索结果需要专用的导入工具，不能伪装成普通对话附件。
- MCP 的 `assets_add` 当前只支持文本和图片。媒资结果应先以画布视频节点或专用媒资引用落位，不能依赖“我的素材”写入接口。
- 当前 Seedance 视频参考最多 3 条，单条 2-15 秒、总计不超过 15 秒，适合把确认后的短片段用于补画面或风格参考，不适合传递整段节目或替代粗剪系统。
- 现有视频节点只有 URL、存储键、尺寸和时长等通用元数据；节目、剧集、媒资版本、时间码、权利和审计字段必须作为新的媒资引用结构补充。

## 业务边界

### 可用的两类输入

1. **电视媒资库内容**：节目、电影、剧集、新闻、预告、花絮及其已标注片段。只有该类内容可以被 Agent 选为正式成片素材。
2. **外部参考内容**：抖音、B 站等解说视频的链接、用户提供的授权文件、文字稿或人工填写的拆解结果。它用于分析选题、叙事结构、节奏和表达方式。

### 不进入首期能力的行为

- 不自动下载、搬运、重新发布抖音或 B 站视频。
- 不把外部视频的画面、音频或字幕直接当作可剪辑素材。
- 不在没有权利信息、地域限制和有效期校验的情况下导出成片。
- 不让 Agent 在未确认前直接发布到外部平台。

外部参考的具体使用方式、授权依据和平台规则需要由业务与法务确认。本方案只把它定义为创作参考，而不是素材来源；正式成片应保留完整的媒资来源和使用记录。

## 目标工作流

```txt
选题 / 栏目要求 / 外部参考
          |
          v
解说与选题策划 Agent
          |
          +--> 文案大纲、叙事节奏、分镜需求
          |
          v
媒资检索与镜头选择 Agent <--> 媒体资源库 API
          |
          +--> 候选镜头、时间码、授权状态、选择理由
          |
          v
画布中的分镜与粗剪流程
          |
          +--> 配音、字幕、AI 补画面、人工调整
          |
          v
渲染服务 / 编辑系统 -> 审片 -> 导出或发布
```

### 画布上的推荐结构

每个短视频项目按从左到右的分组呈现，避免把 Agent 的内部推理和最终素材混在一起：

1. **创作简报**：选题、受众、时长、平台比例、栏目调性、禁用内容。
2. **参考拆解**：外部链接、文本摘要、叙事结构和可复用的表达方式；不保存未授权媒体文件。
3. **脚本与分镜**：旁白、字幕、镜头意图、预计时长和素材检索条件。
4. **媒资候选**：媒资检索结果的缩略图、预览地址、节目名、镜头时间码、权利状态和匹配理由。
5. **粗剪时间线**：已确认的片段、顺序、入出点、旁白和转场要求。
6. **补充生成**：封面、示意图、补镜或转场等生成任务，和原始媒资明确区分。
7. **审片与交付**：预览成片、版本号、审核意见、权利清单和导出记录。

## 媒资接口与数据模型

媒资库应拥有素材的真相来源，前端只获取搜索结果、封面、短时预览和短期有效的签名地址。第一期接口至少需要支持：

| 能力 | 最小接口结果 | 用途 |
| --- | --- | --- |
| 搜索 | `assetId`、节目名、简介、标签、人物/主题、时长、封面 | 按分镜意图找候选素材 |
| 片段定位 | `assetId`、`inMs`、`outMs`、关键帧、转写文本 | 让 Agent 选择可剪辑镜头而不是整段节目 |
| 权利校验 | 可用状态、地区、平台、有效期、敏感级别、禁止用途 | 在选择、渲染和导出前拦截不合规素材 |
| 预览与截取 | 短期签名预览 URL、服务端裁剪任务 ID | 在画布审看并生成粗剪片段 |
| 渲染与审计 | 时间线、素材版本、使用时间码、导出信息 | 交给编辑/渲染系统并保留可追溯记录 |

建议为画布视频节点新增独立的 `metadata.media` 结构，而不是把媒资信息塞入 `content` 字符串：

```ts
type MediaReference = {
  assetId: string;
  assetVersion: string;
  source: "media-library" | "generated" | "user-upload";
  inMs: number;
  outMs: number;
  previewUrl?: string;
  rights: { status: "allowed" | "review" | "blocked"; expiresAt?: string };
  provenance: { queryId?: string; selectedBy: "agent" | "user"; reason?: string };
};
```

媒资资产、片段、预览地址和权限令牌不应进入 localforage 的长期业务数据。浏览器本地只保存画布中指向媒资的引用、短时缓存和当前用户草稿；媒资库负责鉴权、签名 URL、版本和访问审计。

## Agent 与工具设计

首期将“创意规划”和“媒资取用”分开，避免模型直接凭空生成或误用素材。Agent 的关键工具如下：

| 工具 | 权限 | 返回给 Agent 的内容 | 是否修改画布 |
| --- | --- | --- | --- |
| `media_search` | 只读 | 前 10-20 个片段摘要、时间码、缩略图、转写片段、权利状态 | 否 |
| `media_get_segments` | 只读 | 指定媒资的可用镜头和关键帧 | 否 |
| `media_create_preview_clip` | 受控写入 | 服务端裁剪任务、预览片段和来源信息 | 经用户确认后 |
| `media_validate_timeline` | 只读 | 粗剪中的权利、时长、缺镜和重复镜头问题 | 否 |
| `render_create_draft` | 受控写入 | 渲染任务与版本号 | 经用户确认后 |
| 既有 `canvas_*` 工具 | 画布权限 | 节点、连线、选区、生成状态 | 是 |

`media_search` 不应返回整段视频或大体积二进制。它返回足以让 Agent 作判断的结构化摘要，候选片段由用户在画布中预览和确认。`media_create_preview_clip`、渲染和导出必须记录操作者、时间、素材版本、入出点和权利校验结果。

### 首个 Skill

首期只建立一个可审阅的 `tv-short-video-editor` Skill，而非一开始堆叠大量 Skill。它的职责是：

1. 读取创作简报和已有画布内容，先提出可执行的脚本结构。
2. 将每个分镜转成可检索的媒资条件，而不是直接指定素材。
3. 调用媒资检索并在画布中放入候选镜头，说明匹配理由与权利状态。
4. 由用户确认候选后，创建粗剪时间线、旁白和字幕节点。
5. 在提交渲染前检查素材权限、总时长、缺失镜头、旁白与字幕一致性。

后续再从实际高频流程中拆出“影视解说策划”“栏目预告”“体育集锦”“新闻竖屏快剪”等 Skill。Skill 是可版本化的工作指令与工具边界，不应内嵌媒资账号、密钥或未授权素材。

## 分阶段实施

### 阶段 0：媒资接入和人工创作闭环

- 在 `web/src/services/api/` 新增媒资服务封装，使用业务系统提供的浏览器可访问接口。
- 新增媒资搜索与预览选择入口，把已选片段插入画布的视频节点。
- 为视频节点保存媒资引用、时间码、来源和权利状态。
- 用户手动完成脚本、选片和粗剪，确认媒资 API、签名预览和权利字段可用。

验收：编导可以用画布搜索一条已授权节目素材、选取一个时间片段、查看预览，并在导出的项目草稿中保留其来源和入出点。

### 阶段 1：策划与检索 Agent

- 接入 `media_search` 和 `media_get_segments`，默认只读。
- `tv-short-video-editor` 根据简报创建脚本、分镜及素材候选区。
- Agent 只提出候选，用户确认后才创建服务端裁剪片段或粗剪。

验收：输入一个选题后，Agent 能在画布生成 60 秒短视频的脚本和分镜，并为每个需要节目画面的分镜给出可预览、可追溯的候选镜头。

### 阶段 2：粗剪、配音与补画面

- 引入服务端时间线与裁剪任务，生成可审看的低码率粗剪。
- 将旁白、字幕、封面与生成补画面作为独立节点接入。
- 在粗剪时间线中标记生成内容与媒资内容，支持逐镜替换与重新排序。

验收：编导可在画布确认镜头顺序和文案，获得一条带来源清单、旁白和字幕的审片版本。

### 阶段 3：审核、交付与运营接口

- 增加审片意见、版本对比、权利到期告警和导出审批。
- 对接既有编辑系统、渲染系统或发布系统；发布始终由具备权限的用户确认。
- 沉淀项目级数据与审计记录，解决多人协作与跨设备访问；不把浏览器本地项目误当作共享媒资系统。

## 需要确认的产品与接口问题

1. 媒资库是否已有分镜、关键帧、人脸/人物、ASR 转写和主题标签；若无，镜头级检索需要先建设索引。
2. 权利字段能否覆盖节目、地区、平台、账号、时段、二创方式与到期时间；谁是最终放行方。
3. 粗剪和正式渲染由哪套系统执行，是否支持 EDL/OTIO/JSON 时间线，以及音视频转码和字幕烧录。
4. 外部参考内容的输入形态是什么：仅 URL、用户上传的已授权文件，还是由业务系统提供合法的解析结果。
5. 首个目标栏目是影视解说、节目预告、新闻竖屏还是体育集锦；不同栏目决定脚本模板、时长、审查规则和媒资标签优先级。
6. 媒资接口的认证方式、跨域策略和签名预览时效；前端不应持有长期媒资库密钥。

## 本期结论

项目不需要从零做一个视频 Agent。现有画布、Agent 操作协议、视频/音频节点、生成流程和 Skill 管理已经提供了创作编排层。下一步的关键是把媒资库变成 Agent 可检索、可验证、可按时间码使用的“受控视频源”，再让 Agent 在画布中完成策划、候选选择和粗剪编排。

在此之前，不应把“搬运抖音或 B 站解说视频”实现为自动下载与再发布功能。更稳妥的产品路径是：借鉴其叙事结构和选题表达，使用自有或已授权电视媒资重新完成可审计的原创制作。
